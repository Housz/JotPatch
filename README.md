# JotPatch 📌

**随地大小贴。** A tiny, local-first sticky-note layer for Chrome / Edge.

目前版本：**v0.1.14 · 随地大小贴（品牌与颜色偏好）**。继承 Stage 1 的极简便签纸与阶段 0 的文本锚定，新增 ChatGPT / Gemini 对话轮次横条，与原有便签 Dock 融合。

## 体验一览

- **选中文字 → 一个 📌 图标 → 直接写。** 默认不显示「贴便签」文字；在选项里可改为**按住 Alt/Option 才出现**，或**完全关闭弹出按钮**。
- **右键选中文字 →「📌 添加 JotPatch 便签」**：无论选区气泡的模式如何，右键入口始终保留。普通网页主文档内的选区最可靠；若网页清除了选区，仅会在可确定唯一文字匹配时恢复锚点，避免错误关联。
- **没有选区也能记**：点击扩展图标打开很小的快捷区，再按 `+` 创建固定到当前网页的便签。
- **便签就是纸**：无文字标题与原文引文框；现在使用**固定的低对比度顶栏、底栏**，避免图标覆盖文字。整条顶栏（避开操作按钮）可以拖动；右下角缩放整张纸，同时保持左上角不动。
- **多张便签**可同时展开；六种浅色；新建时可在设置中选择固定黄色或随机颜色（同页连续新建不重复）；顶栏一键**复制 Markdown 源码**，底栏只保留加粗 / 斜体 / 项目列表 / 编号列表。
- **小范围 WYSIWYG Markdown**：编辑时直接看见粗体、斜体及两种列表，而不是 `**源码**`；保存与复制是标准 Markdown 文本。支持 Ctrl/⌘+B、Ctrl/⌘+I。`···` 可选小/中/大字号；在纸上按 Ctrl+滚轮调整字号并拦截网页缩放。
- **AI 对话 + 便签 Simple Hover Rail（v0.1.13）**：灰色短线对应提问，彩色短线对应独立便签；按原文比例排列并保持顺序。**无论普通或密集区域，每个可见标记悬停只显示无标题的正文摘要，单击就直达目标。彻底移除弹出的精细选择列表。** 标记纵向位置不随鼠标移动；重叠时仅在极窄轨道内横向错开，避免互相遮挡。
- **可关闭**：设置中的「AI 会话导航」只关闭灰色轮次横线，不影响已有便签标记；若检测到已知的官方轮次导航标记，也会优先收起 JotPatch 的灰色横条。
- **被动历史索引**：用户自然滚动时增量记住已发现的轮次；**没有主动自动滚屏扫描按钮**，不会为了索引历史而改变当前阅读位置。
- **Dock 分层列表**：便签在所属的用户提问下显示，原文关联用紧凑 Pin 图标表达；本页悬浮与待定位便签单独放置。
- **便签 Pin 状态**：原文便签左上角显示一个淡色 Pin，点击可变为本页悬浮便签，并可撤销；悬浮便签没有反向锚定按钮。
- **Dock 保留**：普通网页少量记录使用独立颜色点，密集时也不会合并；锚点不在视口内时便签自动离开视口，返回原文时可继续使用。
- **删除可撤销**：删除后约 8 秒内在提示条中点击「撤销」。
- **本地持久化**：`chrome.storage.local` 自动保存文本、颜色、尺寸、拖动偏移、锚点；既有 Stage 0 `schemaVersion:1` 笔记可直接读取，无需手动迁移。

## 安装与试用

### 从 v0.1.14 ZIP / 源码安装

1. 解压 v0.1.14 安装包；打开 `chrome://extensions` / `edge://extensions`。
2. 开启 **开发者模式**，点击 **加载已解压的扩展程序**；选择包含 `manifest.json` 与 `dist/` 的 **JotPatch 根目录**（不要只选 `dist`）。
3. 进入普通 `https://` 网页（如 ChatGPT / Gemini），点击浏览器右上角的 JotPatch 扩展图标一次。此操作只对当前网页临时授权。
4. 选中文字，点选区旁的 📌；或右键选中的文字选择 JotPatch。对于不依赖具体文字的想法，点击扩展图标，再点小快捷区中的 `+`。
5. 便签顶栏可拖动、复制 Markdown，底栏可格式化；`···` 中改颜色、字号或删除。AI 会话中随着你正常阅读旧消息，Dock 会被动积累已发现的轮次，不需要扫描操作。
6. 想在刷新后无需再次点击扩展图标恢复：通过快捷区中的 ⚙ 打开设置，在**自动恢复**里按站点授权，然后刷新网页。

**更新已有阶段 0 安装**：可以复用同一个解压目录并在扩展页点击“重新加载”。如果换了扩展 ID（例如删除后重新安装另一份 unpacked 路径），旧数据不会自动迁移；**不要卸载原扩展并清空数据后再更新**。

### 使用快捷按钮的三种模式

| 设置 | 行为 |
| --- | --- |
| **总是显示**（默认） | 普通网页中选中文字、松开鼠标后出现小 📌 |
| **按住 Alt/Option** | 鼠标选区结束时仍按住 Alt（macOS 为 Option）才显示 |
| **从不显示** | 不显示选区气泡；使用右键菜单添加 |

> 文本输入框、不可访问的跨域 iframe 选区、`chrome://` 页面以及部分高度动态/虚拟滚动内容并不保证锚定。重复的相同文本会使用前后文消歧，置信度不足时保留便签但提示“原文未找到”，不猜测位置。

## 本地开发

需要 Node 20+；唯一开发依赖是 TypeScript，无运行时依赖。

```bash
npm install
npm run check
npm run test:e2e  # Python Playwright + Chromium（额外安装）
```

`npm run build` 生成 `dist/content.js`、`dist/background.js`。发布 ZIP 中已经包含这些编译产物，可以不安装 Node 直接加载。

## 隐私与限制

- 不联网、不上传文本、不要求账号；不使用任何远程 AI 服务。会话导航只读取当前网页已渲染的用户提问作为临时预览，**不存储完整对话**。
- 仅在点击浏览器扩展图标或右键菜单时使用 `activeTab` 进行临时注入。按网站的自动恢复权限由用户明确授予。
- 右键选中文本属于 Chrome `contextMenus` 权限，启用后即使关闭选区图钉也可使用。
- 单个便签的多标签页并发编辑使用修订号/冲突提示作保守保护，**不保证原子冲突解决**；若提示冲突，先复制本地正文备份再处理。
- 删除撤销窗口不会跨浏览器重启持久存在。建议不要在便签中存放密码或高度敏感资料。

> JotPatch 会在已加载的网页内容上构建轻量导航，并保留网页原有阅读体验。若站点本身结构变动，便签功能仍可独立使用；站点自动恢复可在设置页按网站授权。

## 0.1.7 热修复：虚拟滚动触发意外浮出多张便签

滚动长 ChatGPT 会话时，React 可能临时移除较新的消息 DOM。旧实现只对“锚点存在但滚动出视口”的便签设置隐藏；当锚点 **完全匹配不到** 时，错误地回退到屏幕右侧位置并重现之前展开的便签。

0.1.7 将“锚点丢失”与“纯页面便签”严格区分：锚点缺失、Range 已脱离 DOM 或已在同一文字节点内被替换时，自动隐藏浮层，**不删除便签，不丢失文本、颜色、尺寸或 Dock 记录**。用户主动点击 Dock 中的失效便签时仍可打开编辑。原文恢复后可重新匹配定位。新增模拟虚拟化消息卸载、动态加载、回装和保存一致性的浏览器回归测试。详见 [BUGFIX_0_1_7.md](docs/BUGFIX_0_1_7.md)。


## 0.1.9 导航修复：密集态真实鼠标路径和灰色便签误读

Stage 1.8 的布局单元测试直接调用了私有 `setRailFocus`，并没有证明真实鼠标悬停能展开稳定目标。现在将密集放大移入轨道**左侧的临时展开层**：悬停自动出现，可直接点击每张便签，移出后收起；主轨道坐标不再随着鼠标移动而重排。见 [BUGFIX_0_1_9.md](docs/BUGFIX_0_1_9.md)。

ChatGPT/Gemini 虚拟化可能使原文暂时从 DOM 中消失。以前这会让彩色标记变成灰色；现在保持便签的原本颜色，改以**虚线边框**提示暂时未定位。仍不自动展示已卸载原文的纸张。只有用户主动点击时才打开。注意用户自己选用的“灰色便签”仍保持灰色。


## v0.1.11：有序空间导航

0.1.10 为四张以上同轮便签添加默认多色聚合，但这会打乱用户记忆原文前、中、后的位置，也增加二次选择。**现已撤销聚合设计**。新轨道不使用便签最早/最晚位置对剩余便签重新归一化，优先记录便签占整轮内容的几何/文本位置比例，必要时做最小有序避让。100 轮、60 张便签时启用原轨道局部连续鱼眼，不弹出第二层菜单，默认仍保留每张彩色 marker。详情与限制见 [Spatial Rail 设计文档](docs/SPATIAL_RAIL_0_1_11.md)。


## v0.1.12 — Stable Rail：以准确选择优先

v0.1.11 的鼠标鱼眼会让标记在接近点击时连续移动，难以选中；并且以全局最小间距开启放大，导致无便签的区域也有动画。现在取消指针位置参与 `style.top` 计算，保留实际原文位置比例与独立彩色标记。

普通区域在原位悬停预览、单击跳转，不弹出额外界面。**只有某一小段存在两个及以上相邻便签且间距不足约 9px**，鼠标短暂停留才显示轨道左侧的固定选择区；其中每张便签与相关提问都有稳定的大点击目标。**原轨道本身一律不动**。未能确定点击对象时不会自动选择邻近便签。触发与选中期间停止影响目标的重排，结束后再吸收 ChatGPT 动态加载的变化。全部便签仍可使用键盘与顶部完整目录访问。详见 [Stable Rail 设计与测试文档](docs/STABLE_RAIL_0_1_12.md)。


## v0.1.13 — Simple Hover Rail：不再二次选择

应实际使用反馈，完全移除 v0.1.12 在密集标记区弹出的“附近 x 个导航目标”列表；点击灰色对话短线直接定位 Prompt，点击彩色便签直接定位原文并打开便签。鼠标悬停时两者均显示**只有内容、没有标题或状态行**的微型提示。无论密度多高，用户都不必先操作另一个列表。

针对真实鼠标测试暴露的重叠问题，垂直中心距小于约 7px 的便签在约 29px 宽的轨道里使用最多三个**横向点击通道**，保持它们原本的上下坐标不变。普通分散的标记仍保持旧尺寸与视觉位置。在极限密度、超过三个完全重叠目标时，用户仍可自主打开顶端完整目录或使用键盘方向键；不自动弹窗。详见 [SIMPLE_HOVER_RAIL_0_1_13.md](docs/SIMPLE_HOVER_RAIL_0_1_13.md)。


## v0.1.14 — Logo 与品牌设置

使用 Housz 提供的 16/32/48/128px 官方 PNG Logo 作为扩展和设置页面图标。设置页 slogan 为「随地大小贴」，以低调的 `Powered by Housz` 署名；移除导航中开发期说明性文案。新增新建便签默认颜色偏好：固定黄色（与旧版本兼容）或随机颜色（同一页面连续新建不重复），使用既有 `jotpatch:preferences:v1` 本地设置键，无存储迁移、不增加站点权限。
