# JotPatch v0.1.8 — Passive Conversation Rail / 交互与实现说明

## 决策摘要

此版本根据 Chrome/Edge 的实际使用反馈重构 Stage 1.5/1.6 的导航，而不是新增第二条导航栏。

1. **不再扫描较早轮次**。删除主动自动滚屏与菜单入口；不创建后台副本标签页、不依赖 ChatGPT/Gemini 私有 API。只在用户正常阅读时，从已挂载的 DOM 被动识别和增量缓存轮次；虚拟化的未发现轮次无法保证列出。
2. **对话与便签使用同一条窄时间轴**。每轮灰色横条后到下一轮灰条之前，按照原文顺序放置彩色便签短线。同轮多张便签独立可点击、可悬停预览，不再默认合并为带数字的标记。
3. **自适应空间**。没有便签的轮次分配较小间隙，有便签的轮次自动获得额外空间。极长会话进入密集概览态；鼠标进入某轮区域时，轨道内部暂时为该轮分配更大空间，离开轨道时恢复。不会滚动原网页，也不会打开额外弹窗；焦点保持锁定直到离开轨道，以避免目标在点击过程中抖动。
4. **目录与纸张模式**。列表直接在用户 Prompt 下显示对应便签，正常原文锚定只显示小 Pin 状态标识，不另起“已关联原文”一行。本页悬浮便签及无法可信定位到轮次的便签在底部单独显示。纸张左上角的小 Pin 只支持单向解除原文锚定；带 8 秒撤销。
5. **尽量低权限、低管理负担**。现有笔记存储结构和 `jotpatch:preferences:v1` 保持向后兼容；可选增加稳定的 `conversationTurnId` 字段。会话索引只保存在当前页面内存中，不保存完整对话，不增加网络请求或网站访问权限。

## 视觉布局 / 坐标系统

- 默认轨道位于视口右侧、垂直居中，高度约 68vh；内容实际布局在轨道内部可用高度 `H` 中。列表图标相对整个轨道水平居中，不依赖固定的 `left: 2px`。
- `layoutConversationRail(groups, H, focus?)` 是纯函数：根据顺序排列的轮次和每轮便签 ID，输出独立的 `turn:<id>` 和 `note:<id>` **像素坐标**。通常权重为每轮 14，每张便签 15；每组所获空间随便签数上升。
- 每个组内便签位置混合均匀分布与原文相对先后位置，避免同轮所有便签挤在灰条相同坐标。窗口高度变化时重新求解。
- 当总理想空间大于容器高度，进入密集态。将鼠标移入该轮后，为被选组申请更多局部空间，从其他组借用，但始终保留整条时间轴的顺序。没有额外点击动作；方向键可以逐项聚焦，Enter 跳转。
- 普通网页、AI 对话不足三轮、或已检测到可信原生导航时，保留原有便签-only Dock 行为。

## 源码分层

- `src/content/conversation.ts`: ChatGPT / Gemini DOM adapter；提取真实用户 Prompt，不用回答容器当滚动目标。
- `src/content/conversation-index.ts`: 在用户自然滚动 / React 内容变化过程中保留已发现的稳定轮次 ID。只有可靠稳定 ID 可以跨 DOM 卸载复用；其他轮次仅当次 DOM 有效。
- `src/content/rail-layout.ts`: **新增**独立布局计算；负责普通/密集/聚焦坐标，不碰 DOM、滚动、存储。
- `src/content/app.ts`: 从锚点和轮次建立关联；渲染灰条和彩色独立标记、悬停预览与层级列表；实现 Pin 单向解除和撤销。
- `src/content/paper-styles.ts`: 轨道居中、颜色、密集焦点、小 Pin 状态及菜单样式。

## 数据兼容

`Note.schemaVersion` 继续为 1，保留 `anchor` 与原版记录。新增的 `conversationTurnId?: string` 只在 JotPatch 能从现有 DOM 可信关联到稳定轮次 ID 时写入，用于避免虚拟化卸载消息后把便签错挂到另一轮。如果旧便签没有该字段，则只在能恢复原文并判定轮次后进行一次补写。无法关联时单独放在待定位区，不猜测轮次。

解除原文锚定时清除 `anchor` 和 `conversationTurnId`，但不删除 `text`、颜色、字号、大小等；保存当前位置偏移量以避免便签瞬移。此版本仍是**当前网页的悬浮便签**，不是 Stage 2 的跨网页 Follow 模式；悬浮便签不显示反向 Pin 操作。

## 限制与性能

- JotPatch 不承诺一次性列出聊天全部历史轮次。对于未访问、未渲染的消息，没有安全可靠的标准网页接口可以静默得到完整数据。索引随着自然阅读增加，页面关闭后不持久化会话摘要。
- 虚拟化重用节点、SPA 改版或缺少稳定消息 ID 会降低识别完整度；锚点失效时保持原 v0.1.7 的保护，不被动弹出便签。
- `MutationObserver` 只在有页面 DOM 变化时调度重新发现；用户自然滚动也进行节流检测以应对节点复用，不逐个 token 全文重扫。UI 轨道与便签原文索引独立更新。
- 单轮便签极多、可用高度极小的场景仍有物理空间上限，键盘导航与展开目录作为回退。原始网页不受轨道局部伸缩影响。
- 对话索引依赖非官方 ChatGPT/Gemini DOM 结构，应在每次网页改版后回归验证。

## 验收与测试

```bash
npm run check
npm run test:e2e
```

- Node 测试：布局独立性、顺序、自适应空间、拥挤态、最小窗口高度。
- Chromium 合成 DOM：同轮五张便签独立悬停与点击；100 轮/同轮八张便签局部展开；顶栏图标居中；按轮次分层目录；单向解除 Pin、位置保持与撤销；导航自然滚动发现；原有长对话虚拟化便签不误弹出。
- 测试没有登录用户的真实 ChatGPT/Gemini，MV3 扩展在正式网页中的实际稳定性需要用户本机验收。
