# JotPatch v0.1.12 — Stable Rail / 稳定定位导航

## 目的：先完成任务，再考虑密度

本次根据实际使用反馈修复 v0.1.11 的根本交互设计错误：`handleRailPointer` 每次移动鼠标时调用 `fisheyePositions`，让用户试图点击的目标同时移动；`dense` 是全局状态，一处拥挤导致任意位置都启动放大；空白区域的 `railHitTest` 又可能把无意点击猜成附近的笔记。

设计优先级：**命中准确 > 位置稳定 > 稀疏区一步跳转 > 信息密度 > 动效**。

## 正常使用

- 仍保留 AI Prompt 灰条、彩色独立便签标记、原文几何/文本比例及 PAVA 有序避让。**鼠标移动永远不会改写标记的 `top` 坐标**。普通密度直接悬停预览、单击跳转。
- 点击轨道空白处不再推断最近的目标；不做隐式跳转。
- 取消 `fisheyeCoordinate`、`fisheyePositions`、逐帧 `requestAnimationFrame` 变形和依赖它的视觉动画。
- 原来的便签 Pin/Unpin、浮动纸张、WYSIWYG Markdown、存储结构和可选轮次导航保持不变。

## 局部拥挤才提供精细选择

- `findCrowdedRailGroups` 只考察**便签标记之间**的真实像素间距；相邻便签的纵向中心距小于等于 **9px** 才构成候选，至少两张便签且每组最多 7 张。仅灰色 Prompt 横条密集不触发。
- 每个组可包含该区间附近的少量灰色提问横条作为额外精确目标，仍按原来的纵向顺序显示。
- 鼠标进入该小区域并停留约 **210ms** 才出现**固定位置**的局部精细选择区。原轨道始终保持静态；向左移动进入选择区不会立即消失，彻底离开后约 310ms 收起。
- 点击重叠的可视标记或该局部轨道区域时，会打开选择区，但**不会猜测选择另一张便签**；用户在选择区中明确点击目标。无需聚合数字、颜色变化或连续放大。
- 稀疏的便签完全不受影响，仍然可直接点击；键盘聚焦后按 Enter 可以明确激活当前独立目标，方向键/Home/End 可以沿轨道移动，Escape 关闭选择区。
- 已存在的 100 轮/60 张便签等场景也不会因为非当前区域拥挤而全局放大。

## 动态页面、焦点稳定与隐私

只在**精细选择区打开期间**冻结导航的结构性重建，避免 React 动态加载的消息令用户正在点击的目标漂移。鼠标仅停留在正常轨道上不冻结更新，以免阻止通过右键/选区新增便签实时出现。选择区关闭后自动应用积累的变更。轮次索引仍然仅随用户自然滚动被动发现，不读取 ChatGPT 私有接口，不自动滚动历史内容。

不改变 `Note.schemaVersion:1`、storage keys、扩展权限或现有 Pin 的单向解除行为。原文暂未加载时仍显示原色+虚线边框，原有防误弹逻辑保留。

## 回归方案与验收结果的边界

`npm run check`：TypeScript 构建、契约和纯布局测试，包括灰条-only 密集区不能触发、确实拥挤的局部便签区触发、组内始终保留所有原标记。

`npm run test:e2e`：Chromium 合成页面检验 640px/850px 视口，100 轮/60 张便签，多次真实鼠标跨区、准确点击、点击重叠坐标而不误跳、键盘/ESC、偏离密集区不会激活，以及稀疏便签悬停预览/一步跳转；包含原有 10/50/90%、5/7/9% 比例位置、动态加载时冻结当前选择/退出后更新、虚拟化防误弹和 Markdown 编辑回归。

此测试使用合成网页 DOM 和模拟 chrome.storage；尚需在真实登录的 ChatGPT/Gemini 与完整 MV3 扩展生命周期下继续验收。
