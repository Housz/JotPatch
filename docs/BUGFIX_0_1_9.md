# v0.1.9 — Stable Dense Lens / 密集导航修复

## 可确认的原因

1. `v0.1.8` 密集态通过改变整条 Rail 的坐标实现聚焦放大；鼠标悬停后目标会被移动，导致界面不稳定、局部展开不明显。旧测试使用 `setRailFocus()`，属于直接操作内部状态，遗漏真实鼠标的进入 / 移出路径。
2. `addRailNote` 在原文被 ChatGPT/Gemini 虚拟化移出 DOM 时，将标记背景强制改为 `#a7a7a7`；CSS `.rail-pin.missing` 也覆盖为灰色。这不是存储数据的颜色改变，但从视觉上看像颜色丢失。
3. 用户尚未提供具体的浏览器错误堆栈，不能将网络屏蔽、站点 CSP 等其他扩展或网站错误归因到 JotPatch。此补丁修复的是已在源码和合成网页中确认的问题。

## 修改

- 概览时间轴布局保持固定，只通过独立的 `#jp-rail-lens` 展开局部内容。轨道 **dense** 时，用户的真实指针进入相关区域就能打开展开层，展示 Prompt 和该轮所有便签；不需要额外点击聚合数字。点击目标一次即可直接跳转。移动到展开层时不会失焦，完全离开后自动关闭。
- 原轨道仍保留便签原始颜色；锚点暂时缺失改用虚线描边，不误导为删除或改色。展开层亦采用相同规则。
- 对窗口 resize、Dock 刷新清理旧展开层，不保留过期的 DOM 元素。无新增权限、网络请求或数据字段。

## 实际测试

`npm run check`（TypeScript + Node 契约 / 布局测试）；`npm run test:e2e`（五组原有 Chromium 合成 DOM 回归和一个新增稳定悬停用例）。

关键用例：100 轮 + 同轮 8 张便签、真实鼠标四次进入/退出、640px/850px 视口、概览坐标不变、一次点击直达指定纸张；模拟原文 DOM 卸载/重挂载时保留绿色、虚线提示、便签内容与数量不变。

限制：可用空间充足（不是密集布局）时不会显示展开层，便签点仍直接悬停预览和点击。实际 ChatGPT/Gemini DOM 改版及 MV3 权限仍需要浏览器本机验证。
