# JotPatch 文档类型与验收标准

本规范与 [写作规范](WRITING_STYLE.md)共同用于**新建和正在修改**的文档。项目 Git 分支、权限、数据兼容及发行限制仍由 [AGENTS.md](../AGENTS.md)、[CONTRIBUTING.md](../CONTRIBUTING.md)和 [发行指南](RELEASING.md)约束。

## 文档生命周期与事实来源

- **现行文档**：README、使用指南、架构、开发、版本和发行指南，随实际代码、发行状态及 UI 更新。描述 `dev` 时明确它不同于稳定版 `main`。
- **版本化记录**：Release Notes、导航专题和特定版本 Bug 记录，保留版本、环境、来源和测试范围。
- **冻结证据**：历史故障、实验结果及已发布附件不得因文风统一而重写。新结论放入当前说明或新增注明日期的补充，链接旧记录。

按读者要解决的问题归类；文档可以涉及多种主题，但应有一个明确的主要职责。

## 12 类文档（D01–D12）

| 编号 | 类别及 JotPatch 位置 | 必需内容 | 核心验收 |
| --- | --- | --- | --- |
| D01 | 项目 README：`README.md`、`README.en.md` | 用途、获取、快速上手、主要功能、支持边界、指南及贡献入口 | 初次访问者能安装和使用；中英文事实一致；不堆叠版本流水账 |
| D02 | 操作与开发指南：`docs/USER_GUIDE.md`、`docs/DEVELOPMENT.md`、`docs/FIREFOX.md` | 适用平台、前提、步骤、成功结果、必要恢复路径 | 与实际按钮、权限和命令一致，升级不误导用户卸载清数据 |
| D03 | 研究/历史索引：`docs/PRODUCT_HISTORY.md` 及专题入口 | 按主题链接历史试验、适用版本及后续更正 | 读者能找到原证据，不把被否决交互写成现行产品 |
| D04 | FAQ / 故障排查：用户、Firefox 指南 | 可观察症状、条件、检查步骤、处理结果 | 没有证据不断言根因，不建议破坏存储、绕过浏览器安全机制 |
| D05 | 架构、原理与 ADR：`docs/ARCHITECTURE.md` | 设计背景、组件职责、数据流、取舍及影响 | 对照源码，区分实现、实验和计划；保留已有交互决策 |
| D06 | 类型、接口与格式参考：架构、版本指南、`src/core/types.ts` | 字段、类型、版本、可选性、错误和兼容行为 | 对照实际 Schema、构建脚本、合同测试及浏览器 Manifest |
| D07 | 算法与技术研究：导航恢复/Lab 专题 | 问题、输入环境、方法、结果、证据、限制 | 虚拟化模型、合成测试和真实登录站点不得混为一谈 |
| D08 | 实验、回放与对照：导航/布局实验记录 | 模型、场景、步骤、原始结果、失败和复现入口 | 统计分母、时间和反例真实；不凭单一模拟推断普遍性能 |
| D09 | 测试与验收报告：CI、专题修复记录 | 提交/包、环境、命令、范围、通过/失败/跳过、证据和遗漏 | TypeScript、Node、浏览器合成 DOM、真实安装、真实站点逐级陈述 |
| D10 | Release Notes / 发行说明：`docs/RELEASE_NOTES_*.md`、GitHub Release | 版本、实际变更、兼容风险、安装差异、附件来源 | 与对应 Tag 和附件核对；不改旧发布产物或伪造签名状态 |
| D11 | 政策、Agent 指令、Skill：`AGENTS.md`、本规范、`.agents/skills/` | 适用范围、优先级、禁止越权、执行与检查流程 | 各入口没有冲突；Skill YAML 元数据与链接有效 |
| D12 | 状态、任务与检查点：PR、带日期的开发记录 | 日期、分支、完成/未完成、阻塞、证据、授权边界 | 计划与成果分开，状态快照不覆盖现行指南或历史资料 |

## 分类专属检查

**D01–D04（用户入口）**：采用前提、操作、预期和排查顺序。安装指向当前实际存在的附件；Firefox 签名 XPI 与临时 ZIP 不可互换。故障原因需绑定已复现的浏览器和提交。

**D05–D06（架构和参考）**：给出模块边界和数据生命周期，锚点、`pageKey`、`conversationTurnId`、修订号与软删除行为必须同源码一致。新的站点适配只作为有证据的扩展点，不将示例 DOM 选择器写成线上事实。

**D07–D08（研究和实验）**：写明 ChatGPT/Gemini DOM 来源、合成页面或真实站点、浏览器版本、脚本与代码提交，保留失败和不可达情况。导航耗时、命中率只代表明确的测试场景。

**D09–D10（验收和发布）**：记录实际执行的命令、操作和结果，并指出未执行的实站人工测试。GitHub Actions `success` 不等于 AMO 签名，也不等于特定用户机器上持久安装。签名 XPI 必须标出实际二进制来源；旧 Tag/附件不随文档改写而变化。

**D11–D12（规则与状态）**：Agent Skill 只充当简短路由入口；细节由本规范与写作规范维护。PR 和状态快照不触发合并、打 Tag、发布或签名。

## P0 / P1 / P2 门槛

| 等级 | JotPatch 中的典型问题 | 处理 |
| --- | --- | --- |
| **P0 事实、安全、证据** | 声称未运行的测试通过；把未签名 ZIP 说成可永久安装；丢失便签的误导性升级操作；披露聊天或密钥；擅改旧 Tag/历史证据；未经授权发布 | 阻止合并，核实事实并修复 |
| **P1 内容、结构、一致性** | 安装路径、命令、相对链接错误；Schema、版本或权限不符；签名 XPI 来源未区分；双语 README 关键信息不一致；缺少应有的结果或限制 | 阻止合并，按文档类型补全 |
| **P2 表达和版式** | 重复免责声明、生硬术语、标题模糊、表格过多、段落冗长 | 建议修改；不制定机械禁词表 |

「未验证」「无法保证」在数据完整性和测试/科研记录中可能是 P0/P1 所必需，不应一概删除。

## 文档 PR 检查清单

1. **范围**：只改变授权的文档、Skill 和必要文档验收配置；不借文档 PR 更改扩展源码、版本、签名或发行资产。
2. **结构**：检查标题层级、相对路径、锚点、README 中英文互链和示例命令。
3. **事实**：核对目标 `main`、`dev`、Tag、Manifest、真实 Release 附件及未合并 PR；不要用旧快照替代当前状态。
4. **分类**：对照 D01–D12 所需内容和证据粒度；冻结报告不追溯整理。
5. **双语**：仅规定 `README.md` 与 `README.en.md` 必须成对维护；实验和历史报告无需补译。
6. **验证**：运行适用的文档链接检查（如 `npm run check` 包含的文档测试），记录通过、失败及未运行的浏览器/签名/实站检查。
7. **贡献**：文档分支从 `dev` 派生，PR 目标为 `dev`；是否合并及是否发行由维护者决定。

表达自然与证据充分性需人工核对，自动链接检查不能替代事实审核。移植与改编来源：[XiaomiWatch2HRV 文档类型规范](https://github.com/fcwrwen/XiaomiWatch2HRV/blob/main/docs/development/documentation-types.md)。
